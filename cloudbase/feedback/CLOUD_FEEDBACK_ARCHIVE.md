# 云反馈技术归档

**2026-11-27 首测决定。** 用户在 ZZ Board 中预览反馈，复制或保存本地报告，自行选取可公开的内容提交 GitHub Issue。安全问题走项目的私密报告渠道。首测构建保持云收件关闭；参与试用无需配置腾讯云。此决定取代早期部署清单中把云反馈验收列为首测前置条件的安排。[反馈与贡献](../../CONTRIBUTING.md) · [安全报告](../../SECURITY.md)

## 已实现和验证的部分

| 环节 | 实现与证据 |
| --- | --- |
| 收件与撤回 | 设计中的桌面客户端主动发送经预览的白名单报告。HTTP 函数校验请求，通过受限数据库登录提交报告或凭证撤回；反馈草稿与撤回凭证保存在本机，用户的看板数据库、便签和对话不进入这条链路。相同报告重试返回原回执，撤回后短期保留的墓碑阻止迟到的重试恢复原报告。[传输契约](../../src/shared/feedback.ts) · [收件实现](service.ts) |
| 处理与到期清理 | 维护者在独立收件看板中跟进问题和建议。主表的设计保留期为自接收起 90 天，撤回墓碑保留 25 小时，Event 函数按清理计划移除到期记录。线上实际删除时间取决于清理任务成功运行。[处理状态迁移](../migrations/20261127060000_zzb_feedback_processing.sql) · [清理入口](cleanup.ts) |
| 数据库权限 | 三份迁移依次建立反馈对象、增加处理状态，再将服务操作移入私有 schema。第三份把收件与清理分配给两个独立普通登录，各自只能执行对应操作。真实登录还会继承目标库既有的权限，需按有效权限核对。[基础迁移](../migrations/20261011050000_zzb_feedback.sql) · [专用角色迁移](../migrations/20261127070000_zzb_feedback_scoped.sql) · [数据库适配器](rpc.ts) |
| 本地验收 | 在独立 PostgreSQL 17.10 上，用非超级用户执行三份迁移，两个普通登录通过 TLS 和 SCRAM 认证。实际应用适配器验证了并发重复提交返回同一回执、内容冲突、错误凭证拒绝、撤回后防重放及到期清理。两个登录均不能读取业务表或执行对方的操作。回滚演练保留了无关表与既有登录。另有 17 项 HTTP／驱动测试及 19 项内存 SQL 检查。[HTTP 测试](../../tests/cloudbaseFeedback.test.ts) · [SQL 检查](../../scripts/cloudbase-feedback-sql-smoke.mjs) · [回滚脚本](rollback.sql) |

## 当天的云端证据

| 项目 | 目标环境的实际结果 | 对重新启用的影响 |
| --- | --- | --- |
| 部署与回执 | 三份迁移经官方工具预览；未向云端应用迁移。云函数清单总数为 0，收件与清理均未部署。 | 公共入口回执、凭证撤回、并发去重和定时清理均待云端合成验收。[部署模板](deployment.template.json) |
| 网络与 TLS | 实例详情确认独享 PG 有已启用的私网 PostgreSQL 端点。本机对该端点的一次无凭据 TCP 握手超时。实例 SSL 配置查询未获有效结果，返回了权限提示。 | 须在计划运行函数的网络内验证连接及服务器证书。可在实例「数据安全 → SSL」查看受保护地址与 CA；开启 SSL 会重启实例，须另作运维决定。[实例详情 API](https://cloud.tencent.com/document/api/409/16772) · [SSL 设置](https://cloud.tencent.com/document/product/409/115986) |
| 费用 | 目标为个人版，查询时已开启超额使用。公开套餐表中个人版未包含云函数连接腾讯云 VPC 的能力。 | 重新确认实际权益与费用授权，才能判断私网函数是否可行。[套餐与 VPC 能力](https://cloud.tencent.com/document/product/876/127357) |
| 权限 | 目录只读查询发现目标库已有授予 `PUBLIC` 的读取及执行权限。尚未验证拟设登录只能执行反馈操作，也未取得足以证明普通客户端无法调用清理函数的有效规则。 | 分别测试普通登录、公开客户端及管理端身份。Event 函数即使没有 HTTP 触发器，也要验证 SDK 和网关调用会被拒绝。[数据库账号管理](https://cloud.tencent.com/document/product/409/107909) · [云函数访问控制](https://docs.cloudbase.net/cloud-function/security-rules) |
| 日志与备份 | 环境的 CLS 投递未启用，也没有绑定的日志主题。云开发网关自身的日志保留期与正文采集情况未知。目标实例备份策略的只读查询返回权限提示，未取得数据备份或 WAL 备份的保留天数。 | 需单独说明主表删除与日志、备份副本的可见期限。向有权限的维护者核实备份计划中的两项保留天数，并核对实际网关及函数日志设置。[备份计划 API](https://cloud.tencent.com/document/api/409/68069) · [日志管理](https://docs.cloudbase.net/logger/log/log-management) · [CLS 投递](https://docs.cloudbase.net/logger/log/cls) |

## 将来何时重启

当维护者决定需要应用内收件时，先确定预算与可用网络、取得实际留存说明、验证两个受限登录的权限范围。条件成立后，再用合成报告验收一次完整的提交、丢失回执后的重试、撤回和到期清理，同时确认公开客户端无法读表或触发清理。完成这些检查后再决定启用定时器、开放收件及分发带公共配置的构建。[后端操作说明](README.md) · [部署验收清单](DEPLOYMENT_REVIEW.md)

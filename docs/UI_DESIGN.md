# UI 与 Skin 验收

界面可读性是功能的一部分。此规范源于 2026-09-29 的浅底浅字按钮问题：入口没有控件样式，浏览器默认底色与 Skin 继承文字组合失配；纯源码测试未发现实际颜色错误。

## 实现规则

- 新按钮、下拉框使用 `styles.css` 的低优先级默认控件样式；组件可调整布局、尺寸、图标和层级，不依赖浏览器默认底色。重要入口要有明确命中范围、名称和键盘焦点。
- 普通控件使用成对的 `--control-bg / --control-text`；悬停使用 `--control-hover / --control-hover-text`。强调按钮使用 `--control-accent / --on-accent`，不固定写白色。焦点使用 `--control-focus`。
- 画布背景、界面 Chrome、便签是不同配色域。工具浮层与表单使用界面控件配色，不借画布 `--paper` 搭配界面文字；便签正文与编辑器继续使用 `--note-skin-text`，不覆盖用户选择的便签 Skin。
- 禁用不等于不可读：保留文字，使用禁用语义、光标、边界及邻近说明，不把整个按钮降到低透明度。选中不能仅靠一个很淡的色差；保留描边、标记或文字状态。
- `skinRuntime.ts` 为控件解析不透明底面，并优先保留 Skin 色彩；不足时选择可读的前景。此保护不重写、拒绝或升级已有自定义包，不代表任意混搭的画布文字和纹理已自动合格。

## 每次 UI 变更的检查

便签单击原位编辑，双击正文进入专注。检查中文组字、粘贴图片进行中和保存失败时的切换，再看专注便签上方三个图标在窄窗口是否可达。优先级在两套内置图标中各有立起与跃起两种姿态，也可使用看板自己的两张图片。

1. 运行 `pnpm check`。`controlPalette.test.ts` 覆盖官方 V1/V2 背景与 V2 Chrome 组合、危险自定义色、文字/悬停/禁用配色、焦点与边界、旧变量移除。CSS 检查阻止固定白字强调色按钮和低透明度禁用控件回归。
2. 启动 `pnpm exec vite --host 127.0.0.1 --port 5175 --strictPort`，在允许的独立 Chrome 中访问 `http://127.0.0.1:5175/tests/browser/controls.html`。页面只用合成内容，不连接正式数据或模型。点“检查全部 Skin”，阅读实际计算样式的对比度报告；新增控件族时扩展这个样例。
3. 检查四套官方 V2、四套保留 V1、深浅跨域混搭。普通文字对比目标 4.5:1；必要的控件边界与焦点目标 3:1。计算样式检查不能代替对渐变、透明叠层、纹理的实际验图。
4. 在 1366×768 与 1920×1080 核对默认、悬停、键盘焦点、选中、禁用、加载、错误、长中文和窄栏。打开对话浮窗、色板、导出面板，检查遮挡、换行、尺寸、关闭入口和滚动。切换 Skin 后不得残留旧配色。
5. 桌面交付前用正式 WebView2 核对对应入口。浏览器/原生验收受阻时必须在版本报告列为未完成，不能用单测 PASS 宣称已验图或“所有地方都没有问题”。

保持克制：一致的字级、留白、边界和状态比给每个按钮单独加渐变更重要。默认兜底防止遗漏，不替代新功能的设计与验收。

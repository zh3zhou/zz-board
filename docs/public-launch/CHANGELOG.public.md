# ZZ Board 更新记录

此文件只保留公开基线之后的可分发记录。日期表示本次源码候选记录时间，不表示 GitHub Release 已经发布。

## 未发布

新建 Windows 看板使用「夜墨 3.0」。桌面源码发行采用已定稿的 Source Available 1.0，署名李哲舟（Li Zhezhou）。

[网页试用](https://zh3zhou.github.io/zz-board/)打开一张合成书展画布，可以写便签、贴图、涂画和连线，改动保存在当前浏览器。Windows 源码新增只读部署预检，缺少 Node 时也能输出工具和端口检查结果。私人试用构建支持本机诊断事件的预览和手动导出。

公开首页增加作者介绍、整张合成画布和自用版便签缩略图。Codex 联动指引显示如何让空白看板接入第一个项目，以及从项目对话存下带来源的便签。从源码运行的用户可明确执行 `-BindCodex` 关联正在使用的桌面。

打开程序直接进入画布。「数据与帮助 → 使用指南」提供便签、项目整理和 Agent 定制说明。便签支持单击原位读写、双击专注、居中插图和长文滚动。

「项目 → 项目更新 → 来源授权」分别控制本机读取和模型整理。新看板默认关闭每日检查。过去启用过每日检查的看板在重新授权后，先核对选定的本机项目，成功后再安排下一次每日检查。源码项目提供部署说明、维护手册和 Skin 工具。Agent 从源码建立桌面入口，以后可在同一项目里继续定制。

使用独立 Windows 用户配置从源码构建桌面并原址升级后，旧便签的中文和图片仍可读。新 Agent 可以核对运行中的窗口、数据与源码位置，并制作、校验和预览 Skin；样板连线采用所选 Skin 的颜色和宽度。

反馈收件和过期清理现在分别使用受限的数据库登录。本地 PostgreSQL 已验证并发重试、凭证撤回和到期清理。官方首测采用本地报告与 GitHub Issues，在源码发布时开放问题和建议表单。CloudBase 路线另行归档。

复核后修正等待期间撤销授权的后续读取守卫，并在总结进程退出时释放自身管道。准备检查只报告已读取的本机身份与模型目录，实际模型请求、剩余额度和总结运行时安全检查分别验证；制作 Skin 优先读取匹配源码内的 Skill。

源码导出与封包可显式使用同一记录日期；封包期间固定该日期，已有源码清单拒绝冲突日期，避免跨 UTC 日期导致摘要不一致。

# ZZ Board：从画布使用到长期维护

在自己的源码项目里，可以让 Agent 构建桌面、制作 Skin，也可以问它看板数据存在哪里。日常打开程序会直接进入画布。需要帮助时，从「数据与帮助」打开「使用指南」。

日常可以先用便签、图片和画笔，再按需接入 Codex 项目近况。需要定制时，让 Agent 在源码项目中阅读该版本的 `README.md`、本手册和 `AGENT_CUSTOMIZATION.md`，编译完整桌面交付物；随后仍回到这个源码项目维护版本 README、测试记录和下一次改动。不要在已打包 EXE 中直接修补功能。

新建看板采用「夜墨 3.0」。到「外观 → 皮肤库」可选择其他皮肤。项目源码及随附自有素材的授权条件见 [许可全文](../LICENSE)。

## 先选一条路径

| 你现在要做什么 | 入口 | 不会发生什么 |
| --- | --- | --- |
| 记录和整理 | 直接在画布双击空白处，或按 `N` 新建便签 | 不读取 Codex、不调用模型。 |
| 看已保存的项目 | 左上菜单 →「项目」；需要更新时在项目详情明确点「检查更新」 | 普通浏览不补读原对话。 |
| 看帮助或恢复线索 | 左上菜单 →「数据与帮助」 | 打开手册不改变画布。 |
| 制作外观或改功能 | 回到**匹配版本源码项目**，交给 Agent 阅读本手册和定制说明 | 不自动安装 Skill、替换 EXE 或发布。 |

## 五分钟使用画布

1. 首次使用，在这个项目里让 Agent 按[部署指南](DEPLOYMENT_QUICKSTART.md)从源码构建桌面。从它交付的稳定入口打开应用。写便签可以直接开始。
2. 打开后直接进入画布。按 N 或双击空白处写第一张便签。编辑时粘贴一张图片，它会在光标处居中独占一行。点正文继续编辑，双击进入专注模式。点纸面留白可以选中整张。画笔、橡皮擦等工具在左下角。
3. 想找对话时，点画布左上角，在「项目」里搜原始对话标题，或从「待我处理」定位来源。首次接入时，在「项目更新」查看读取与模型授权，再选一个本机项目检查。

在 Codex 的对应项目里，可以说“用 `$save-zz-board-note` 把刚才的决定和还没解决的问题记成一张便签”。如果只想审阅，指定“先预览”。已保存的便签连到项目气泡，来源入口能帮助找回原对话。需要待办时说“把刚才的下一步做成一张待办便签”。打开便签详情可逐项勾选。在对应的 Codex 项目里说“用 `$read-zz-board-project` 读最新便签，看看图片并解释它们的位置”，也可以给出便签 ID。看板里点项目详情的「便签」，可以展开已连接的完整图文，再定位到画布。

“反馈与帮助”先预览再发送。未配置服务时可以复制报告；只有有效回执才表示已接收。联系方式和诊断都是自愿提供，不默认遥测。

## 安排工作、换背景与复盘

悬浮或用 Tab 聚焦便签可以看到上次编辑时间，有日期或标记时才显示相应信息。点便签，在「安排」选择关注或优先，也可以只记一个日期。开启日期升档时，默认提前 7 天关注、1 天优先，手动标记作为最低档。完成本次期限会保留日期并结束自动升档。快捷键 1 设优先，2 或旧的 3 设关注，0 清除手动档。

在「外观」可以打开皮肤库，也可以直接给全板或当前页选本机背景图。点「布置与绘制」移动、缩放和叠加图片，或在上面画线。在「背景收藏」可以另存并载入多套布置。调好透明度后点「应用背景图」。同一外观页还可比较两套猫图标，或分别选图表示关注和优先。恢复继承可找回全板外观。单页皮肤背景和个人图片可以相互切换。

在项目对话中对 Codex 说「用 `$read-zz-board-project` 看看我上次记下的技术取舍，下周先验证什么？请引用便签。」想回顾多个项目，可以说「用 `$review-zz-board-week` 总结上周实际发生的事」。默认回顾上一个完整的本地自然周，手动试读后也可在 Codex 里另选每周的运行时间。没有安装副本时，可让 Codex 使用匹配源码目录下 `skills/` 中同名的 Skill。

## 页面、迁移与归档（0.11 源码候选）

页面可以容纳多个项目，也可以只放自己的便签、图片和笔迹。每页记住各自视口，项目筛选作用于当前页。项目气泡只有一个位置。从「待我处理」或跨页查找点对话名，看板会定位到对应项目并高亮那条对话。点「在 Codex 打开」可进入本机原对话，其他来源可复制定位信息。

跨页移动沿用混合选区。已经明确收入宿主的便签默认一起移动；附近内容或仅用连线相连的便签需明确选入。组内相对位置、原图引用与真实关联保留，异页关联提供跳转，移动一次撤销。气泡的“全部折叠／展开全部”整理合法下游内容并保留原位置，不生成摘要或调用模型。

页面归档后可以只读查看。该页项目自动检查暂停；已发出的当前读取或模型请求可以完成，已产生用量不会撤回，后续请求暂停，其他页项目继续。恢复页面后仍保持暂停，点击继续自动检查才重新遵循全局开关与原授权；也可以在活动页明确检查一次。把项目移到其他页后遵循目标页的检查状态，移动本身不立即发起检查。用户主动导入的新快照或摘要仍能更新归档项目的来源内容。

新发现的项目进入指定接收页，已有项目同步原地更新。归档接收页前先指定另一张活动接收页，至少保留一张活动页；只有真正没有内容的页面可以删除。每页可选择已安装 Skin 的背景组件或继承全局，其余界面外观保持全局组合。

切页会先完成编辑收尾及本地恢复副本；中文组字、未完成图片上传或保存冲突需要先处理，不能靠强行卸载编辑器绕过。离线草稿、图片重试和迟到视口保存仍属于发起页面。退出重开、开机／解锁及原生输入验收状态见版本记录，不把源码候选说明视为已通过验收。

| 自由绘制、整理空间 | 画笔、荧光笔、套索、选择、适应视图；坐标随画布保存 | 我想把几个想法连接起来，解释画笔、套索和缩放的差别。 |

| 看 Codex 项目近况 | 全源采集指令与本机检查各有覆盖范围；不会操作来源任务 | 先说明会读取哪些项目、多少条对话和预计模型用量，再让我选择。 |
| 看对话和项目历程 | 最近对话窗口、按需补更早回合、只读文档历史预览 | 只整理这个项目最近三条本机对话，不补全部历史，说明不可读部分。 |
| 撤销或恢复 | 编辑器撤销与画布撤销分开；完整快照导入是历史屏障；证据同步不进入画布撤销链，永久删除不能撤销 | 解释哪些操作可以撤销，如何完整备份再升级。 |
| 导出或反馈 | 区域 PNG、快照、主动反馈；快照不包含完整图片和历史 | 帮我检查反馈预览是否包含隐私，不自动提交。 |
| 扩展交互 | 修改源码，遵守工程合同并验证 | 先读 AGENTS.md 与 agent.project.yaml，提出最小改动和验证，再实现。 |

## 五个仓库 Skill：用途和权限

这些 Skill 的编辑源都在源码项目的 `skills/`。先让 Agent 读取匹配版本的仓库副本；安装到用户目录是另一项持久机器改动，必须单独同意。

| Skill | 适合何时使用 | 会读/会写什么 |
| --- | --- | --- |
| `review-project-progress` | 汇总当前项目的停点、决定和待办 | 默认只读来源；明确同步时才提交有界证据。 |
| `read-zz-board-project` | 让 Agent 读取一个项目已保存的便签、图文和关联 | 只读本地看板的该项目范围。 |
| `save-zz-board-note` | 将明确决定或下一步写为带来源便签 | 先预览；只有明确保存才写入本地看板。 |
| `review-zz-board-week` | 回顾选定本地周内已经保存的事实 | 只读本地看板记录。 |
| `create-zz-board-skin` | 制作、校验和打包声明式 `.zzskin` | 可在你选定目录写候选皮肤；安装和应用仍要你明确选择。 |

`pnpm validate:skill` 检查仓库 Skill；`pnpm validate:skill:installed` 只比较已安装副本。`pnpm sync:skill` 先预览，只有明确批准后才运行 `pnpm sync:skill -- --apply`。此命令面向用户级安装。首次连接稳定桌面时，用部署指南的 `-BindCodex` 建立本机绑定，然后直接使用仓库 Skill。

## Codex 首次准备与授权

ZZB 内的同意、Codex 的登录、Agent 的文件/命令权限是三件不同的事。

- **本地读取**：允许读取既有范围内的本机项目、任务和明确选择的项目记录。准备过程会检查登录与模型目录，首次可能扫描本机会话元数据并建立本地索引；这一步不做模型生成，但不是完全不读历史文件。初始化可能需要数分钟。
- **模型调用**允许把选中对话的文字证据交给当前 Codex 登录使用的模型。默认配置为 `gpt-6.2-sol / medium`。已有看板保留手动保存的模型选择。
- **文件修改、安装或云端写入**：由用户对 Agent 明确提出，并受 Codex 自身权限机制约束。ZZB 的同意不代替这些权限。

保存两项授权后，先选一个本机项目检查最近三条对话。原先开启的每日检查等这次成功后再安排，新看板默认关闭每日检查。在「项目 → 项目更新」可看下次时间。你可以随时撤回授权，已经发出的模型请求仍计入用量。

## 用量怎么判断

| 操作 | 模型用量说明 |
| --- | --- |
| 便签、图片、画笔、Skin、本地帮助 | ZZB 不调用 Codex 模型，模型 token 为 0；如果你另请 Agent 帮忙，对话仍有自己的用量。 |
| 准备登录/模型目录和索引 | 不生成总结；只读准备不等于一次模型请求，可能有本地时间/磁盘开销。 |
| 本机检查 | 有界读取；证据未改变时复用总结。发现变化才可能调用模型。 |
| 文档历史补充 | 预览提供所选文档输入 token 的字符估算；不包含全部提示、输出或推理，不能当作最终账单。 |
| 首次采集和总结 | 未选择输入前无法给可靠数字。先缩小到一个项目；采集 Agent 与 ZZB 独立总结分开计量，输出和推理在完成前未知。 |

总结回执记录 input、cached input、output、reasoning 和 total。缓存属于输入、推理属于输出，不能再相加计算第二次。取不到计量显示未知，不能填写 0。

**token 不能固定换算为 Plus 的 X%。** 额度还受模型、推理、上下文、缓存、工具及账号窗口影响。ZZB 尚未接入实时账户额度；在 Codex `/status` 或官方用量面板查看已用百分比和重置时间。ChatGPT 登录消耗订阅额度；API Key 是另一种按量计费身份，本项目不会自动切换。

官方依据：[登录](https://learn.chatgpt.com/docs/auth)、[权限](https://learn.chatgpt.com/docs/agent-approvals-security)、[用量](https://learn.chatgpt.com/docs/pricing)、[CLI 命令](https://learn.chatgpt.com/docs/developer-commands#built-in-slash-commands)。说明核对于 2026-10-11，账号实际显示优先。

## 找到实际运行入口与数据路径

不要凭源码目录名、任务栏标题或某个旧 EXE 推断正在使用哪份数据。先在源码根运行 `pnpm setup:windows -- -Status`：它报告已配置的入口、数据目录、WebView 目录、EXE/源码版本与哈希、进程/窗口和本地 health 是否一致；没有来源凭据的既有安装会明确显示未知。只查看结果，不要据此猜测或扫描其他目录。

Windows 桌面程序优先读取本机绑定 `%USERPROFILE%/.codex/zz-board.json`：其中的 `desktopExecutable`、`projectRoot` 和 `dataDir` 是实际入口、对应源码根和数据目录。没有绑定时，才使用启动时的 `ZZ_BOARD_PROJECT_ROOT` / `ZZ_BOARD_DATA_DIR`；两者都没有时，数据目录才是 EXE 所在项目根下 `.local-data/`。WebView2 profile 位于实际 `dataDir/webview`。开发时可运行 `pnpm board -- status --ensure-running` 检查所连服务是否与绑定的 `dataDir` 对应；它只接受 loopback 服务。缺少绑定时，必须同时明确提供 `--desktop-exe` 和 `--data-dir`，不要猜测或扫描磁盘。

## 完整备份、恢复与更新

退出应用前保存编辑，使用托盘「真正退出」，再按照上一节核对实际 `dataDir`。已有绑定优先于环境变量；不能仅设置变量就认为是空白试用。

完整备份应复制同一次关闭后的整个 `dataDir`，至少包括 `zz-board.sqlite`、`media/` 原图/预览、`skins/`、日志和摘要运行时状态，以及其中的 `webview/` profile；不要只导出快照。若要恢复未发送反馈草稿和删除凭证，还须先导出删除凭证。浏览器配置文件和看板数据都需要保留，二者缺一都可能失去未发送状态。

恢复时先把备份复制到一个新的、隔离目录，使用匹配版本启动并核对便签、媒体和皮肤；确认后再在已退出的正式程序上做可回退替换。不要让 Agent 删除数据库来“修复”，也不要用旧程序打开已经写入新字段的数据。`pnpm setup:windows -- -Rollback` 只在数据与记录快照一致时更换程序文件/对应资源；遇到迁移或数据变化会要求先另存当前 `dataDir`，不应把它当成数据格式回退。

## 源码维护与桌面交付

在源码根目录使用 `pnpm`：先 `pnpm install --frozen-lockfile`，日常开发用 `pnpm desktop:dev`，共享改动至少运行 `pnpm check` 与 `pnpm smoke:windows`。需要让 Agent 编译可审阅的桌面候选时使用 `pnpm desktop:build`，再运行 `pnpm desktop:smoke`。需要由受控入口构建并部署到现有本机位置时使用 `pnpm setup:windows -- -Build -Deploy`；追加 `-Start` 才打开部署版，`pnpm setup:windows -- -Start` 只打开当前已部署版。构建或部署成功不等于已经完成原生输入验收或允许公开发布。

维护顺序是：在源码中定位和验证 → 生成完整桌面候选 → 更新该版本的 README/变更说明和证据 → 以后仍从同一源码项目继续。Skin、数据契约和桌面运行时的具体入口见 [Agent 定制](AGENT_CUSTOMIZATION.md)。
